The runner is up. The UI is not here.

ghostclick is two repositories. This one holds the runner and the control plane; the app you are looking for is built in ghostclick-web and handed to this server as a directory.

Mount it

The usual answer, and what the production compose file does. Build the UI in its own repository, then bind-mount the result over /app/ui:

cd ghostclick-web
VITE_AUTH_URL=https://your.host npm run build

# .env.prod
GC_WEB_DIR=/srv/ghostclick-web/dist

The address in VITE_AUTH_URL is baked into the bundle at build time, so a UI built without it shows no sign-in at all, whatever this runner is configured to require.

Or bake it into the image

cp -r ../ghostclick-web/dist ./web-dist
docker build --build-arg GC_WEB_SRC=web-dist -t ghostclick-runner .

Or point the server somewhere else entirely

GC_WEB_DIR=/some/other/build node server.js

Everything that is not the app is working meanwhile: /healthz says whether the browser came up, and /api/version says which commit this is.
